# Convico backend

Minimal Next.js App Router API for Convico text and voice chat. `POST /api/chat` accepts `{message,history,requestId}` and returns `{reply}`. `POST /api/voice` accepts multipart `audio`, `durationSeconds`, `history` (JSON), and `requestId`; it returns `{reply,audioToken}`. `POST /api/tts` accepts `{text,audioToken,requestId}` and returns a generated WAV file. Errors use `{error:{code,message,retryAfterSeconds?}}`.

## Setup

1. Get a Gemini API key from [Google AI Studio](https://aistudio.google.com/app/apikey). Copy `.env.example` to `.env.local` and enter the key. Keep it on the server; never put it in the Expo app or a `NEXT_PUBLIC_` variable.
2. Create an Upstash Redis database and set `UPSTASH_REDIS_REST_URL` and `UPSTASH_REDIS_REST_TOKEN`. This shared store is required: AI requests fail closed without it. It tracks IP rate limits, a global daily budget, concurrent requests per IP, request IDs, and a provider-quota circuit breaker.
3. Install dependencies with `npm install`. For local development use `npm run dev`.
4. Import this GitHub repository in Vercel as a Next.js project. Set `GEMINI_API_KEY`, `GEMINI_MODEL`, `GEMINI_TTS_MODEL`, `TTS_SIGNING_SECRET`, and both Upstash variables in Project Settings → Environment Variables. Generate `TTS_SIGNING_SECRET` as a random secret of at least 32 characters; keep its value stable so issued voice tokens remain valid. Set `LIMIT_REQUESTS_PER_IP=30`, `LIMIT_WINDOW_SECONDS=60`, and `LIMIT_DAILY_REQUESTS=200` in Production, or remove these variables to use the defaults. The old `LIMIT_DAILY_SAFETY_PERCENT` variable has no effect and can be removed. Redeploy after environment changes.
5. In the Expo app, set `EXPO_PUBLIC_API_BASE_URL=https://your-backend.vercel.app` in its local environment or build configuration. For a physical phone during local development use the computer's reachable LAN IP (for example `http://192.168.1.10:3000`), not `localhost`.

## Limits and security

Default application controls: 30 AI requests per public IP per 60-second window; 200 accepted AI requests across the app per rolling 24 hours; up to four concurrent requests per IP; 2,000 message characters; 10 history entries; 3 MB audio and 120 seconds duration. The daily budget is a conservative development default, not a Gemini quota estimate. Review actual Gemini usage and costs before raising `LIMIT_DAILY_REQUESTS` for production growth. Text chat, voice processing, and first-time TTS each reserve one request. Playing audio already saved on the device makes no API call. Change the limits through `LIMIT_*` environment variables. A unique request ID is consumed before calling Gemini, so a repeated request cannot generate twice. When an IP or the app budget reaches its limit, the API returns HTTP 429 with a distinct error code, `retryAfterSeconds`, and a `Retry-After` header. Rejected requests never call Gemini. There are no automatic retries or model switches.

The app has no login. IP limits can affect people sharing a public IP, and IP identity depends on Vercel's trusted proxy headers. Keep deployment behind Vercel and add verified user authentication before public release if per-user quotas are needed. CORS is optional via comma-separated `APP_ALLOWED_ORIGINS` for browsers and is not authentication. Requests without an Origin header are accepted for native clients. Do not place a shared secret in the mobile bundle. A signed token ties each TTS request to an actual voice reply. TTS shares the IP limit. Speech is generated only when Play is tapped; the app saves the WAV file on the device for later playback. Redis stores counters and request IDs, never audio.

The old `convico:daily` Redis key is no longer read or written; the new budget uses `convico:daily:v2` with a 24-hour TTL starting at the first accepted request. The rate key uses a `convico:rate:v2:` prefix, so old hourly counters do not delay the new minute policy. Google's model limits vary by model, account, and tier; check [your active limits](https://ai.google.dev/gemini-api/docs/rate-limits) in AI Studio. Our limits cannot guarantee a number of successful Gemini calls. After a provider quota response, `convico:provider-quota:chat` or `convico:provider-quota:tts` remains set in Redis. The prior `convico:provider-quota` key is also honored for chat. Once you have confirmed the relevant quota is available in AI Studio, manually delete the corresponding key to resume requests. The backend does not guess Google's reset time. `GEMINI_MODEL` defaults to `gemini-3.6-flash` and must support text and audio input; this model returned real text and voice replies in Production when `gemini-2.5-flash` returned upstream 404 for generation. `GEMINI_TTS_MODEL` defaults to `gemini-2.5-flash-preview-tts` and supports speech output; its [free tier is listed by Google](https://ai.google.dev/gemini-api/docs/pricing), but availability and limits depend on the project and may change.

Vercel Functions currently cap request and response payloads at 4.5 MB. This backend caps uploads at 3 MB to leave multipart overhead, TTS output at about 4 MB, and uses a 45-second function duration. Voice text replies are limited to 600 characters to bound audio output. Check [Vercel's current function limits](https://vercel.com/docs/functions/limitations) for your plan; provider latency and other account limits can still cause failures. Audio duration is supplied by the app and checked, while byte size and MIME type are checked server-side. A production service needing a hard audio-duration guarantee should inspect audio metadata with a suitable parser.

No secrets belong in Git history. `.env.local` and other `.env` files are ignored; `.env.example` contains placeholders only.

If `/api/chat` returns `AI_SERVICE_UNAVAILABLE`, check the Vercel Function log entry `Gemini generation failed` for the upstream HTTP status. `401` or `403` usually means the configured key or project access needs attention; `400` can indicate an invalid model or request. The backend intentionally logs no key, prompt, or audio. Confirm `GEMINI_API_KEY` and `GEMINI_MODEL` in Vercel and redeploy after changing them. A working backend must return a real `{reply}` to a valid chat request; a successful Next.js build alone does not prove provider access.

Gemini provider failures, missing model access, quota exhaustion, blocked output, incomplete output, and empty output have separate safe error codes. Vercel logs contain only API status and error code, upstream status and error class, finish reason, block reason, and aggregate output token counts when available. No keys, user messages, tokens, or audio are logged. `X-Convico-Diagnostics`, `X-RateLimit-Limit`, `X-RateLimit-Window`, and `X-Convico-Daily-Limit` on error responses show the deployed diagnostic code and effective limits; they do not indicate that Gemini itself is available.
